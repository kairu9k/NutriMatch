# Full app test plan (backend, frontend, every page, desktop then mobile)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to run this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Every bug found goes through superpowers:systematic-debugging before it is fixed.

**Goal:** Check that every NutriMatch page works for its role on desktop and then on a phone, fix what is broken, and leave a findings log the team can show the panel.

**Approach:** Run the automated checks first (Django tests, Nuxt build). Then build one throwaway test world in a scratch database: an admin, an RND, a client and the records each page needs. Drive the real app in Chrome through the Claude in Chrome tools, one role at a time, at desktop width (1288 px) and then at phone width (390 px). The user's dev database and the site on port 3000 are never touched.

**Tech stack:** Django 6.1.1 + DRF (backend tests), Nuxt 4 (build), Claude in Chrome (browser), scratch SQLite database.

**Spec:** the user's request on 2026-11-16 ("test everything backend frontend UI, all the pages, desktop first then mobile"), CLAUDE.md (rules per feature, design rules) and the memory notes on mobile, buttons and dropdowns.

## Global constraints

- Never use `backend/db.sqlite3` or Neon. The test world lives only in `scratch.sqlite3` (`DATABASE_URL` set explicitly), served by a backend on **127.0.0.1:8001** and Nuxt on **127.0.0.1:3001** (`NUXT_IGNORE_LOCK=1`, `NUXT_PUBLIC_API_BASE=http://127.0.0.1:8001/api`).
- User's call (2026-11-16): **real emails yes, SMS no, PayMongo in test mode, real image uploads (Cloudinary), no video call** (already tested). The test-run Django tests still run with email/SMS blank. The scratch backend keeps the Gmail settings from `.env` and runs with `SEMAPHORE_API_KEY=` blank.
- Test accounts use plus-addresses of the project's own inbox (`nutrimatch36+client@gmail.com` …), so every email lands in one inbox the team reads. PayMongo is paid with PayMongo's published test card on its test checkout page; the webhook points at Render, so the local invoice turns paid through the Billing page's sync (`invoices/sync/`).
- The test-world script lives in the session scratchpad, not the repo (adviser dislikes seeders). Their password is kept only in the test-world script, never in chat or in `vault/test-logins.txt`.
- Work in a new Chrome tab and never sign in on the user's own tabs. Leave the test tabs open at the end.
- Desktop = 1288 × 928. Mobile = 390 × 844 (iPhone 12-class, what DevTools shows the adviser).
- Mobile pass rule (memory): no sideways scroll (`document.documentElement.scrollWidth <= innerWidth`), the form comes first, pop-ups listed in CLAUDE.md go full screen, tap targets aren't squashed.
- Design rules from CLAUDE.md apply to every page: sentence case, no " · " or "→", filled buttons with one height per row (green = action, light green = secondary, red = destructive), `nm-select` dropdowns, toasts for actions you can't otherwise see, allergies always red.
- Fixes follow the existing rules. No new features, test frameworks or dependencies unless the user asks (memory: no over-engineering).

## Review focus

1. **Empty states:** a brand-new account with no records. Each page should say what to do next, not show a blank panel or an error.
2. **Long text and many items:** a long name, a long note, 25+ rows. Expect text to wrap, lists to page at 20, and no overflow on a phone.
3. **Pop-ups on a phone:** booking, NCP form, screening, summaries, lab file. Each opens full screen, its buttons stay reachable, and it doesn't scroll the page behind.
4. **Role leaks:** a client opening an RND or admin URL, and the other way round. Expect a redirect, never another person's data.
5. **Console errors and failed requests:** none on any page load or main action (checked with `read_console_messages` and `read_network_requests`).
