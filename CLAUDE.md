# NutriMatch — Project Notes

Capstone project (STI College Davao, BSIT) — *NutriMatch: Web-Based Clinical Nutrition Consultation Management System*. Full proposal: `vault/C1-NUTRIMATCH-FINALv5.pdf`.

## What it is

Connects clients with licensed Registered Nutritionist-Dietitians (RNDs) in the Philippines for structured Medical Nutrition Therapy (MNT), built around the clinical **4-phase Nutrition Care Process (NCP)**: Assessment → Diagnosis (PES statement) → Intervention → Monitoring & Evaluation. This is a real standardized clinical methodology (Academy of Nutrition and Dietetics) — not an invented workflow, so don't restructure it without checking the proposal.

Three roles: **client**, **RND**, **admin**.

## Stack (current — deviates from the original proposal)

- **Frontend:** Nuxt 4 + Tailwind CSS + Lucide icons. Lives in `frontend/`.
- **Backend:** **Django 6.1.1 + DRF + SimpleJWT**, lives in `backend/`. The Laravel implementation was fully deleted (not kept as reference) — `vault/C1-NUTRIMATCH-FINALv5.pdf` is the authoritative reference for domain logic, and the Django models (`backend/*/models.py`) are the schema (the old DBML `vault/database.txt` was retired 2026-10-11 once everything was implemented — it's in git history). This is a deliberate stack change from the originally-proposed Laravel+MySQL — approved by the user, don't second-guess it or suggest reverting.
- Original proposal's documented stack was Laravel 11 + Nuxt.js 3.10 + MySQL 8 — no longer applicable, superseded.
- DB: SQLite for dev (`backend/db.sqlite3`); production reads `DATABASE_URL` (`dj-database-url`, `psycopg`) — **Neon Postgres**. **Deployment (2026-10-20, user's call — free, no card):** backend on **Render** free web service via `render.yaml` (daphne, `rootDir: backend`, Singapore, migrates on start since the free plan has no pre-deploy/shell; `RENDER_EXTERNAL_HOSTNAME` is added to `ALLOWED_HOSTS` automatically), static files via WhiteNoise (`STATIC_ROOT=staticfiles`), HTTPS settings (proxy SSL header, SSL redirect, secure cookies, HSTS 30 days) only when `DEBUG=False`, `CSRF_TRUSTED_ORIGINS` from env; frontend on **Vercel**. No Redis needed (one process → in-memory channel layer). Free Render sleeps after 15 min idle (~1 min to wake). `seed`/`createsuperuser`/data copies are run locally against Neon's `DATABASE_URL`. **Live URLs:** frontend `https://nutrimatch-theta.vercel.app`, API `https://nutrimatch-api.onrender.com/api`; production admin `nutrimatch36@gmail.com` (password set via Forgot password). **Email in production goes through Brevo's HTTPS API** (`core/brevo_email.py`, `BREVO_API_KEY` on Render only) because Render's free plan blocks SMTP ports; locally Gmail SMTP (20 s timeout) or the console. Brevo's IP review was turned off (Render's outbound IPs change). PayMongo test webhook `hook_3kvfs7ALhb3ULVFdU9BrtmPg` points at the Render URL. Render + Vercel auto-deploy on every push to `main`; new env vars must be added by hand. Neon needed `nutrition/0010` (category code was 11 chars > varchar(10) — Postgres enforces lengths, SQLite doesn't).

## Domain constraints that matter for implementation

- **Calculations must match named clinical formulas** — Mifflin-St Jeor equation (BMR), TDEE derived from it, **WHO Asia-Pacific BMI thresholds** (not standard global WHO cutoffs), NRS-2002 nutritional risk scoring. These are specified in the proposal; don't substitute generic formulas.
- **Food sources (updated 2026-10-12, user's call — USDA is in the proposal's objectives):** FNRI Food Exchange Lists stays the default and the only source for diet templates and exchange counting; **USDA FoodData Central is now the second source** (`nutrition/usda.py`, key `USDA_FDC_API_KEY` in `.env`, free at https://fdc.nal.usda.gov/api-key-signup). RND-only endpoints `GET /api/usda/foods/?q=` (generic foods: Foundation / SR Legacy / FNDDS, per 100 g) and `GET /api/usda/foods/<fdc_id>/`; responses cached in `core.ApiCache` for 30 days; blank key → 503 "not set up", USDA down → 502. Used by Meal Planning (**Add from USDA**, `UsdaFoodPicker.vue`, portion in grams) and the USDA tab on Food Exchange Search. A USDA meal-plan food stores only `food_name` + `source_type=usda` + `external_food_id` (FDC id) + `MealPlanFoodItem.grams`; its kcal/macro columns stay empty and `MealPlanFoodItemSerializer` fills them live from the cached per-100 g values (`usda.item_nutrients`, frontend `utils/usda.js usdaPortion`). Not yet in the 24-hour recall (that counts by FNRI exchanges).
- **Data minimization still applies to whatever food source is active**: **only `food_name` (plain text) may be persisted from any external lookup — never store the full nutrient payload.** This is an explicit RA 10173 data-minimization design decision from the proposal, not an oversight — preserve it when building the FNRI integration.
- **NCP records are one longitudinal record with 4 phases**, not 4 separate tables — confirmed in the proposal's data model; `frontend/app/components/NcpRecordModal.vue` implements it this way (the initial record leaves Monitoring empty).
- **RA 10173 (Data Privacy Act) compliance is a first-class requirement**: audit logging (immutable `audit_logs` rows), RBAC, encryption in transit, informed consent. Explicitly out of scope per the proposal: formal NPC registration, end-to-end encryption, automated data retention schedules, granular consent revocation — don't add these unless asked.
- **Invoices/commission amounts freeze at creation** — don't let commission calculations recompute retroactively.

## Design rules (user's calls, 2026-10-24 RND design pass — keep new UI looking hand-made, not generated)

- **Text:** sentence case everywhere (labels, buttons, titles); no all-caps labels or tracked-out eyebrows; join details with commas, never " · "; no " — " inside sentences (use a full stop, comma or colon); no "→" on links or buttons. A lone "—" is fine only as an empty table/figure cell.
- **Colour meaning:** dashed green (`1.5px dashed #3f9a6b`, white background) = something still to do (`.nm-note.todo-note`); red = real warnings only (allergies, clashes, overdue, NRS risk); grey (`.nm-note.plain-note`) = plain information; dividers `#d9e3dc`; main buttons dark green `#0a4a37` (hover `#00382a`). Gold stays for stars, brand marks and where the user asked for it — check before swapping gold for green.
- **Shadows:** light `0 0 1px rgba(0,77,58,.06), 0 0 14px rgba(0,77,58,.09)`; strong (pop-ups, floating button) `0 0 2px rgba(0,77,58,.08), 0 0 24px rgba(0,77,58,.22)`. Green banner gradient `linear-gradient(135deg,#00382a 0%,#005a42 100%)`.
- **Structure:** figures in one divided panel (cells split by `#d9e3dc` lines), not rows of small boxes; numbered markers only for real sequences; motion only to draw attention to one thing, inside `prefers-reduced-motion: no-preference`.
- **Allergies are never quiet:** any food picker or plan view that knows the patient's allergies shows matches in red (`utils/foodWarnings.js allergyWarnings`).
- **Edit pages** (Profile Settings) are read-only until **Edit profile**, with Cancel / Save changes at the bottom.
- **Buttons (user's rule, 2026-10-24):** every button is **filled** and buttons in a row share **one height** (36px, `nm-btn-sm` 32px). **Green = do something** (`nm-btn-dark`, `#0a4a37`, Pay/Upload/Save/Book on every page); **light green = secondary** (`nm-btn-soft`, `#e3efe7` + dark green text: Back, Close, View, Print…); **red = destructive** (`nm-btn-danger solid`: Cancel, Delete, Remove). **Gold is for notices and brand, not actions** (status labels/dots like Payment due, stars, logo, banner date); the only gold button is one sitting on the dark green banner. No outlined or text-only action buttons, no "→". `nm-panel-link` is now a small filled light green button; a name or number inside text or a table cell uses `nm-text-link`. Long lists already in memory page 20 at a time with `usePager(list, { resetOn })` + `<ListPager>` (`.nm-pager` on the panel's bottom edge).
- Don't name a Tailwind utility as a class (`ring`, `shadow`, `border`…) in scoped CSS — Tailwind styles it too (the blue ring around the dashboard earnings chart).

## Working conventions

- **Philippine time on the server's clock (user's rule, 2026-10-22 — no device-date tricks):** backend "today" decisions use `core/ph_time.py` (`ph_today()`, `ph_date()`), never `timezone.localdate()`/`date.today()` (UTC — a day behind before 8 AM PHT); dates a client could fake are decided by the server (meal logs: the day is always the server's PH date, a different `log_date` is refused, a meal planned for another weekday can't be logged). Every response carries `X-Server-Time` (epoch ms, `core/server_time.py`, `CORS_EXPOSE_HEADERS`); `frontend/app/plugins/00.ph-time.client.ts` makes `toLocale*String()` default to Asia/Manila and `new Date()`/`Date.now()` follow the server clock (offset synced in `useApi`), so changing a phone's date/time changes nothing. Use `utils/phTime.js` (`phIso`, `phWeekday`, `phHour`) instead of `getFullYear()/getDate()/getDay()/getHours()` for "today" logic.
- **No emoji in text fields (user's rule, 2026-10-15):** `plugins/no-emoji-inputs.client.ts` silently strips emoji (typed or pasted, no message) from every text input and textarea app-wide, in the capture phase before v-model. Only notes and messages keep them, via `data-allow-emoji` (chat inputs, support message/replies, booking notes, meal-log note, reading note, RND private/NCP notes, payout notes) — add that attribute to any new notes/message field. Frontend only; the API doesn't check.
- **Chat only while care is active (user's rule, 2026-10-15):** sending a message (REST `POST /api/relationships/<id>/messages/` and the WebSocket consumer) needs the relationship `active` — i.e. the RND confirmed a booking; pending (a booking waiting) and discharged are refused (403 / ignored). Reading history is always allowed. `?include=ended` on `/api/client/relationships/` and `/api/rnd/relationships/active/` adds discharged care and pending care with a booking waiting; Messages shows them read-only, tagged Ended / Waiting. A discharged client who books again reopens the care as pending; if that booking is declined or cancelled with nothing else waiting, `scheduling.services.close_reopened_care_if_idle()` sets it back to discharged. Pickers keep the default (active only).

- **Dropdowns are one style app-wide (user's rule, 2026-10-12):** every native `<select>` uses `class="nm-select"` (`assets/css/portal.css` — custom arrow, focus/disabled/`invalid` states; add `block` for full width in forms). Don't style selects per page (page CSS may only set layout like width), and prefer a native `nm-select` over a custom pop-up menu; a searchable picker (PES problem, measurements) should match its border, radius, padding and font.
